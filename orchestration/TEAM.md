# 공공·민간 AX 연구·대시보드 팀 운영

구성일: 2026-09-06. 사용자의 요청에 따라 팀장이 목적별 모델과 작업을 배정한다. 사용자는 팀장인 현재 대화 상대에게만 요청·수정·승인을 전달한다.

## 조직과 모델

모델의 일반적 강점에 대한 [OpenAI 공식 모델 안내](https://developers.openai.com/api/docs/models)를 참고하되, 위 업무 배정은 이 프로젝트를 위한 팀장의 판단이다. 모델 선택만으로 연구의 타당성이 보장되지는 않는다. 현재 실행 도구가 지원하는 모델 ID와 추론 수준을 명시해서 시작한다. 공식 API의 추론 옵션과 이 대화 도구의 옵션은 같다고 가정하지 않는다.

동시 실행은 이 세션 기준 **팀장 포함 4명**이다. 모든 역할을 항상 켜 두지 않고, 검토가 끝나면 구현·검증 역할로 작업을 넘긴다. 과거 `ax_dashboard_ui`, `hccp_independent_framework`, `wps_ax_implementation`의 완료 결과는 보존하고, 모델이 명시된 새 작업은 `data_audit`, `literature_review`, `causal_review`로 시작했다. 기존 에이전트의 모델을 바꿨다고 주장하지 않는다.

## 오케스트레이션 순서

1. **팀장 접수:** 사용자의 목적·변경사항을 하나의 작업 목록으로 관리한다.
2. **독립 업무 병렬 배정:** 자료 담당은 문항을, 문헌 담당은 원문을 확인한다. 파일 소유권을 겹치지 않게 배정한다.
3. **방법론 심사:** 실제 측정·표본·시점이 가설을 지지하는지 판단한다. 인과 표현이 불가능하면 필요한 가정과 한계를 명시한다.
4. **팀장 통합:** 근거가 충돌하면 원문·코드북으로 되돌아간다. 미확인을 다수결로 확정하지 않는다.
5. **구현:** 사용자가 요청한 변경 범위 안에서 승인된 분석 명세만 코드와 화면에 반영한다.
6. **검증·보고:** 반복 검사와 실질적 통계 검토를 구분하고, 실제 완료·미완료·배포 여부를 팀장이 보고한다.

보고 공통 항목: `발견 → 원문/문항 위치 → 검증 방법 → 한계 → 변경 파일 → 다음 조치`. 공공·민간의 차이는 직접 대비와 불확실성을 제시한다. 통계적 유의성을 보고 변수를 골라 이야기를 만들지 않는다.

## 첫 검토 작업 결과

첫 자료·문헌·인과 검토와 기본 문서 검증을 완료해 팀장이 아래에 통합했다. 여기서 완료는 **문헌·사전 감사의 한정된 작업 범위**이며, 미확보 논문 본문·원자료 회귀 재현·대시보드 재배포까지 끝났다는 뜻이 아니다.

- [종합 변수·방법론 검토](../DATASET_STUDY_METHODS_REVIEW.md): 팀장 통합, 자료별 역할과 미확인 사항.
- [한국미디어패널 자료·문항 감사](../KMP_AX_SUITABILITY.md): Terra 담당, SAV 사전·설문 대조.
- 로컬 기록 `reports/SUPPLEMENTAL_STUDIES.md`: Sol 담당, KIPA 2편과 KMP 1편.
- 로컬 기록 `reports/CAUSAL_REVIEW.md`: Astra 담당, 주 모형과 인과 표현 검토.
- 로컬 기록 `reports/TEAM_QA.md`: Luna 담당, 통계 심사와 별개인 구조 확인.

위 `reports/`는 공개 저장소에 포함하지 않는 내부 검토 기록입니다. 공개 근거와 한계는 연결된 종합보고서 및 각 분석 안내를 기준으로 확인합니다.

팀장은 인과 검토에서 지적한 시간 순서 표현을 고치고, 신규 자료의 측정 범위·표본 분모와 문헌의 확인 수준을 종합보고서에 반영했다.

## 후속 구현 작업 (2026-09-06)

사용자의 “작업해 그럼 이제” 요청으로 구현 단계에 들어갔다.

- `analysis_engineering` — Terra High: 동일 코호트 로짓 민감도, 분리 검증, WPS/HCCP 근거 메타데이터. 준완전분리가 확인된 로짓은 수치 게시를 보류한다.
- `dashboard_engineering` — Terra High: 근거·자료 탭, 문헌·자료 범위 필터, 확률/로그오즈 단위 및 보류 상태 표시.
- `literature_review` — 기존 Sol XHigh 재사용: 14개 문헌 카드의 실제 통제변수·표본·근거등급 교차검증.
- `release_statistical_review` — Astra Ultra: 구현 담당과 독립적으로 분리 판정·추론·비게시 계약을 최종 검토.
- 팀장: 역할별 산출물 통합, 원자료·자격증명 업로드 제외, 통합 테스트, 기존 Vercel 프로젝트 배포와 사용자 보고.

로컬 구현 검토 기록 `reports/IMPLEMENTATION_REVIEW.md`와 공개 [배포·검증 기록](../DEPLOYMENT_STATUS.md)을 구분해 남긴다. 모델 설정 명세를 설치형 서버로 바꾸거나 사용자 전역 모델을 교체하지 않았다.

## 자료 재구성 실행 (2026-09-06)

사용자의 HCCP 제외·기타자료 추가 요청에 따라 Terra High 두 자료 담당과 기존 구현 담당을 병렬 배정했다. 공공 담당은 KIPA 2015·2019·2022의 42문항을 로컬 재집계하고 사용허가 확인 전 공개 숫자를 차단했다. 개인 담당은 지능정보패널·미디어패널을 검증하고 한국어 문항 및 동일인 전이를 구현했다. 팀장은 노동패널2018의 24문항과 전자정부2024의 39문항·공개 파이프라인을 맡았다. Astra Ultra는 각 결과의 분모·측정·인과 주장 및 공개 조건을 독립 검토했다. 사용자와의 확인은 팀장만 수행했다.

HCCP 원자료·과거 분석은 로컬에 보존하며 활성 앱과 배포 입력에서 제외한다. 신규 자료는 기술통계이며 기존 WPS 다중회귀와 구분한다. 모든 역할은 이 대화의 실제 하위 에이전트 작업이며 별도 상시 실행 서버를 추가하지 않았다.

## 팀장 승인 위임과 누락 회수 (2026-09-07)

사용자는 일반적인 human-in-the-loop 중간 결정을 팀장에게 위임했다. 기획 선택·시각 조정·재시도·테스트·보완 작업은 사용자에게 매번 확인하지 않고 팀장이 승인해 진행한다. 팀원이 일을 놓치거나 근거 없이 완료를 보고하면, 팀장이 산출물을 확인해 직접 보완하거나 재배정한다.

- 로컬 `reports/OVERNIGHT_PLAN_20260907.md`: 시작 00:01:41·목표 종료 06:01:41 KST, 6시간 기준의 검증 가능한 업무 블록.
- [공개 비교 분석 명세](../KIPA_COMPARISON_METHODS.md): KIPA 2024 생성기·가중/표준화 재현의 결손과 후속 직접 대비 조건. 기존 계수를 바꾼 분석이 아니다.
- [의사결정 정책](decision-policy.json): 일상 작업의 팀장 위임, 게시 전 검사, 새로운 권한 필요 여부를 분리한다.
- [실행 가능한 정책 검사](decision-policy.mjs): 일반적인 작업의 진행 판단과 담당 모델, 완료 보고의 누락을 JSON으로 반환한다. 대화형 질문이나 승인 대기 입력은 없다.
- [회귀 테스트](../tests/orchestration-policy.test.mjs): 일상 작업 자동 진행, 팀장 모델 유지, 공개 전 검증, 누락된 산출물·미실행 검사·실패한 독립 심사 회수, 권한 우회 금지를 검사한다.

예시:

```powershell
node orchestration/decision-policy.mjs repair_failed_work
node --test tests/orchestration-policy.test.mjs
```

정책 코드 자체가 에이전트를 호출하거나 외부 작업을 수행하지 않는다. 실제 하위 에이전트의 배정·재배정·최종 통합은 현재 팀장이 수행한다. 출력 `proceed`는 **프로젝트 내부 판단**일 뿐 운영체제·실행 도구의 권한 승인이 아니다. 인계 검사도 증거의 존재 여부를 정리할 뿐, 분석의 진실성이나 통계적 타당성을 자동 인증하지 않는다.

원자료 공개·비밀키 노출·권한 우회는 허용하지 않는다. 기존 공개 저장소·집계 결과·Vercel 배포·홍보영상·커밋/푸시는 이미 승인된 범위로 처리하되 검증을 생략하지 않는다. 새 비용이나 외부 연락, 실질적 범위 확대 등은 사용자 권한을 새로 필요로 한다. 실행환경의 권한 제한을 코드로 없애지 않는다. [OpenAI의 Windows 권한 안내](https://learn.chatgpt.com/docs/windows/windows-sandbox)와 프로젝트 권한 경계를 구분한다.

## 설정의 적용 범위

`team.json`은 역할·모델·업무분장 명세이고, `AGENTS.md`는 다음 작업에서도 팀장이 참고하는 프로젝트 지침이다. **자동 실행 서버나 설치된 API 오케스트레이터는 아니다.** 이번 실행에는 대화의 실제 하위 에이전트 기능과 명시적 모델 옵션을 사용했다. [Codex 공식 하위 에이전트 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents)는 명시적 모델/추론 배정과 역할 구성을 설명한다.

사용자 전역 설정, `.codex`의 보호된 설정, API 키, 권한, 배포 보호 설정은 바꾸지 않았다. 팀장 대화 모델도 이 명세가 변경하지 않는다. 별도 서비스·지속 실행·사용량 과금 한도·앱 내 모델 선택 UI는 추가 구현 범위이며, 만들어졌다고 보고하지 않는다.
